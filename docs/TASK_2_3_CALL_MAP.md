# Задача 2.3 — карта миграции сетевых вызовов (обновлена 2026-11-12)

Аудит путей Control Plane и нижних границ сервисов в `master` для задачи 2.3. Обозначения: **N** — понадобится TEMPEST после отдельного проектирования `NetworkPlan`; **L** — legacy/не нужен для MVP; **H** — опасное изменение хоста, не входящее в контракт Agent v1. Вызов может иметь несколько категорий. Agent mode не применяет реальные сетевые операции; typed inspection не означает переноса apply.

## Первая проверяемая часть

`CONTROL_PLANE_MODE=agent` — **явно включаемый** профиль миграции. `DEV_SAFE_MODE=1` имеет приоритет и сохраняет прежний dev-safe Compose/no-op контракт. Новый профиль допускает только health/auth и авторизованные `NetworkPlan` validate/diff/status через типизированный AF_UNIX клиент. Остальные HTTP/WS пути получают `501 NETWORK_PLAN_OPERATION_UNSUPPORTED`; dataplane dispatch и `_apply_nftables` отказывают до прямого вызова. Никакого успешного apply через mock Agent нет. Флаги `LEGACY_ROUTER_ENABLED`, `LEGACY_WIFI_DHCP_ENABLED`, `LEGACY_SSH_DEPLOY_ENABLED`, `LEGACY_DOCKER_SIDECARS_ENABLED` по умолчанию выключены; даже их включение не открывает заблокированные endpoints в Agent mode, пока реализации не перенесены.

По умолчанию остаётся legacy поведение PiTun ради совместимости; legacy profile не является безопасным режимом установки на хост без дальнейших работ. В Agent mode VPN трафик пока **недоступен**. Статус `2.3` включает только планирование/inspection и fail-closed изоляцию: он не обещает перенести реальные mutation в Agent. Обоснование разделения с 2.5–2.6 зафиксировано в `PROJECT_SPEC.md`.

## Проверенный срез 2026-11-12: DB-derived plan inspection

- `backend/app/network_agent/plan_builder.py` — чистый builder legacy `Node`/settings → v1 `NetworkPlan`. Он включает только enabled Node ID/protocol metadata, строит следующее поколение от Agent `read_status`, не сериализует адреса/credentials и не добавляет interface, route, allow policy или implicit DIRECT. Каждый план содержит mandatory protected-ingress block; статус Agent не idle, пустой набор узлов, некорректный `active_node_id`, неизвестный protocol и лимит более 64 enabled nodes fail closed.
- `POST /api/network-plan/current/validate` и `/current/diff` формируют план из DB и вызывают только typed `ValidateRequest`/`DiffRequest`; `GET /current` позволяет просмотреть результат. `/status` сохраняет typed `ReadStatusRequest`. Все пути остаются под текущей HTTP auth.
- Typed client проверяет тип результата для каждого метода и отличает Agent rejection от отсутствия/некорректного IPC. Ошибки conflict возвращаются как HTTP 409, invalid plan/configuration — 422, отсутствие/повреждение IPC — 503. Apply по-прежнему не имеет клиентского вызова.
- Перенесено в Agent inspection: DB-derived план-кандидат, validate, diff и status. Не перенесены реальные network mutations, routes/interfaces/firewall, Xray/engine lifecycle, health probes/failover, host DNS/network apply, router/Wi-Fi/DHCP, Docker sidecars, remote SSH deploy и их managers.
- Agent-mode middleware продолжает закрывать все unmigrated HTTP/WS API, а startup остаётся DB-only. Прямые internal calls теперь дополнительно fail closed на сервисной границе: `network_config.host_run`, network apply/rollback/DNS, nftables command/apply, TUN setup/teardown, router/IP forwarding/WAN/Wi-Fi bridge/DHCP/Wi-Fi/sidecar/resource-limit operations, SSH remote command/upload/job, updater request, Xray runtime API/config writer/lifecycle и system host toggles/settings. Guard выполняется перед subprocess, file write, Docker client, SSH connection и engine lock/process lifecycle. Все эти операции остаются недоступными, а не перенаправляются через NetworkPlan.
- Запуск legacy health/failover, circle, auto-check, geodata, subscription, drift, LAN scan, router-watchdog и Docker-sidecar supervisor schedulers тоже отказывает в Agent mode до создания фоновой задачи; прямые health failover и circle rotation отказывают на callback boundary.
- Xray process/config lifecycle отделён собственной `require_legacy_engine` guard: это явная будущая граница CP↔engine и не произвольная host command/NetworkPlan v1 operation. Это изоляция текущих сервисов, не новый engine adapter.
- В Agent mode remain unsupported: nftables/ip rule/route/TUN apply; Xray/engine lifecycle; health probes/failover; host DNS/network apply; router/Wi-Fi/DHCP; Docker sidecars/resource changes; remote SSH deploy; updater and host toggles. Реальное применение принадлежит только 2.5–2.6 после ownership design и VM испытаний. Вне NetworkPlan v1 остаются router/Wi-Fi/DHCP, Docker sidecars, SSH deploy и system-wide DNS.
- Existing integration risks are not changed: process-local replay bound, missing durable pending/LKG recovery, unverified systemd sandbox/capability masks and UID/GID/cgroup mapping. Legacy operation remains available in `CONTROL_PLANE_MODE=legacy`; `DEV_SAFE_MODE` retains its middleware/no-op behavior.
- Regression tests directly invoke service internals with subprocess/file/Docker/SSH/engine effects mocked and assert refusal occurs before those effects. Existing tests continue to cover IPC failure/rejection, absent Agent, invalid DB config, conflicting Agent state, forbidden DIRECT, concurrent inspection and HTTP/WS deny behavior.

## Открытые риски Agent

- Replay cache содержит не более 4096 request IDs только в памяти процесса; при заполнении отказывает новым ID, после рестарта теряет историю.
- Нет durable pending/LKG recovery после crash/reboot. Успех mock Apply не означает изменение сети.
- Systemd unit проверен статически, но runtime sandbox/capability masks и `NetworkNamespacePath` не испытаны.
- UID/GID/cgroup и PID mapping из контейнера к systemd Agent не проверен на целевой Linux VM.
- ADR-001 остаётся `PROPOSED`; netns/nftables/WG/IPv4/IPv6/DNS tests не проводились.
