# Working Core — VLESS TCP/Reality

В разделе «Провайдеры и выходы VLESS» укажите название и провайдера, выберите «Ручной ввод», затем «TCP/Reality». Укажите числовой IP, порт, UUID, DNS-имя сервера (SNI) и публичный ключ. Если сервер требует short ID или Vision, укажите соответствующие значения. Можно также импортировать одиночную ссылку или [смешанную подписку TLS и Reality](WORKING_CORE_SUBSCRIPTIONS.md). Для домена в адресе URI укажите dial IP вручную. SNI используется при рукопожатии, соединение устанавливается с указанным IP.

| Параметр URI | Поддерживаемые значения |
| --- | --- |
| `security`, `type` | `reality`, `tcp` или `raw` (по умолчанию TCP) |
| `sni` | DNS-имя, настроенное на сервере |
| `pbk` | Публичный X25519 ключ, 32 байта в Base64URL без padding |
| `sid` | Пустое значение или до 8 байт в hex, по две цифры на байт |
| `fp` | `chrome` (по умолчанию), `firefox`, `safari`, `ios`, `edge` |
| `flow` | Пустое значение или `xtls-rprx-vision` |
| `encryption`, `headerType` | `none` или отсутствие параметра |
| `spx` | Пустое значение или `/` |

Xray 26.10.31 с `xtls-rprx-vision` сам отклоняет UDP/443. Flow `xtls-rprx-vision-udp443`, нестандартные `spx`, PQ-параметры, TLS pin совместно с Reality и другие транспорты отклоняются на входе. Панель и Xray Agent должны использовать одну версию TEMPEST для применения нового формата Reality.

Сохранение выхода и подтверждение импорта добавляют записи в каталог. Для перехода на новый выход сначала выберите его в черновике, затем отдельно выполните preview/apply. После применения сохраняются прежние правила DIRECT/VLESS/BLOCK и default BLOCK. При отказе проверки нового поколения Agent возвращается к рабочему LKG или закрывает ingress.

## Проверка · 2026-11-20

Проверены ручное сохранение, смешанный импорт с предпросмотром, дедупликация, ревизии, шифрование и отсутствие параметров Reality и UUID в ответах API и открытом тексте БД. Закреплённый Xray 26.10.31 принял конфигурации всех пяти fingerprint с Vision и без него, а также прежний TLS с pin через `run -test`. Работоспособность живого туннеля предстоит проверить. Блок B остаётся в работе.

На согласованной disposable VM проверьте:

1. Вручную добавьте один Reality-выход, второй импортируйте из смешанной подписки. Убедитесь, что трафик продолжает идти через прежний выход после добавления и выбора в черновике.
2. Примените профиль без flow, затем профиль с Vision. Для каждого проверьте TCP, UDP и DNS через WireGuard, а для Vision отдельно подтвердите ожидаемый отказ UDP/443.
3. Проверьте неверные short ID и публичный ключ, а также недоступный upstream. Убедитесь, что защищённый трафик не переходит на DIRECT, а неудачное применение возвращает рабочий LKG или закрывает ingress.
