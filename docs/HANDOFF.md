# AWG egress — передача на TORNADO, 27.11.2026

## 27.11.2026 · DNS-адаптер: WIP, реальная VM NOT_RUN

На TORNADO подготовлен экспериментальный **sing-box 1.14.2** только для DNS. GOST 3.3.3 исследован первым: его DNS handler создаёт DoT exchanger без TLSConfig; в использованном upstream `go-gost/x v0.28.1` это включает `InsecureSkipVerify`. Такой вариант не удовлетворяет обязательной проверке сертификата и не интегрирован. sing-box скачан из официального релиза: Windows archive SHA-256 `c2d8bfff918755808781dfdeeb8581b6c91eb3a243d9a7b55483cfc0c0684d32`; Linux archive `a684484d7477d1437282ee411f4d131d0340aaad60a7868841ebd5d87dd8a0c6`; извлечённый Linux amd64 binary `fc9c6e6ab345f045b16a0ed10d1ff28d68e8e56e7749fca30738d1406e98d7b8`. Бинарники не добавлены в репозиторий. sing-box распространяется под GPL-3.0-or-later: перед поставкой отдельно проверить обязательства распространения и уведомления зависимостей; пока используется внешний операторский бинарник.

`scripts/lab/dns-adapter-synthetic.py <путь к sing-box>` проверил на loopback TCP и UDP, DNSKEY >512 байт без TC по TCP, SOCKS5 с обязательными учётными данными, числовой IP назначения, SNI, отказ при несовпадении имени и недоверенном сертификате, отказ при остановке SOCKS и имитации недоступного upstream без прямого подключения к работающему тестовому TLS-серверу. Это синтетическое доказательство адаптера, не Xray → AWG и не доказательство всей DNS-политики. Системный DNS, маршруты и firewall не менялись. Закреплённый Xray 26.10.31 и sing-box приняли сгенерированные конфигурации через свои config checks. Targeted Windows pytest: 31 passed, 11 skipped; отдельный test verifier: 1 passed. Linux-only AF_UNIX/SO_PEERCRED и systemd runtime: `NOT_RUN_ON_WINDOWS`. Реальная AWG VM, внешние DNS и CI/CodeQL: `NOT_RUN`.

Для нового поколения AWG оператор **явно** задаёт `awg_dns` в защищённом deployment profile: числовой IPv4 `address`, сертификатное имя `server_name` и необязательный `port` (по умолчанию 853). Никакой DNS-провайдер не выбирается автоматически. Без этого поля сохраняется прежняя UDP-схема с её ограничением; старые LKG и fingerprints должны оставаться читаемыми. Пример для ручной проверки подходящего сервиса: `{"address":"1.1.1.1","server_name":"cloudflare-dns.com","port":853}`; применимость и политика провайдера ещё не подтверждены. В новом поколении Agent валидирует бинарник/config, запускает AWG → DNS → Xray и сохраняет DNS config в fingerprint/LKG; SOCKS credentials находятся в закрытом файле, не в аргументах. Ошибка восстановления закрывает ingress по существующему контракту. Успешный config check или запуск процесса не подтверждает передачу DNS.

## Блокер DNS

Простые запросы клиента TCP/UDP проходят, но Xray переписывает upstream на UDP и большой TCP DNSKEY ответ приходит с TC. Полноценный DNS не подтверждён. Прямой TCP DNS через AWG SOCKS к испытанным resolvers отклонялся; отдельная TLS-проба к DoT через SOCKS однажды прошла. Попытка встроить DNS-over-TLS через Xray DNS outbound и dialerProxy не дала ответов по TCP/UDP; кандидат отклонён, эксперимент удалён, возвращён UDP LKG и предупреждение панели.

Следующий шаг: исследовать DNS/TLS dialer Xray и возможность полноценного TCP DNS через существующую цепочку; при необходимости оценить проверенный DNS-прокси с SOCKS/TLS. Сохранить fail-closed, LKG и не восстанавливать отозванные ключи. Не считать наличие простого ответа доказательством полноценного DNS.
