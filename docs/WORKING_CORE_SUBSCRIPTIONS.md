# Working Core — импорт подписок VLESS

В разделе «Провайдеры и выходы VLESS» создайте провайдера, откройте «Импорт подписки VLESS» и выберите его. Вставьте список URI по одному на строку, тот же список в Base64 или укажите HTTPS-ссылку. Поддерживается VLESS TCP/TLS, как при одиночном импорте. Для домена из URL узла укажите пару `домен IP` на отдельной строке, сохранив TLS-имя из ссылки. Сервер не разрешает домены самих выходов.

Предпросмотр показывает, какие строки будут добавлены и почему остальные пропущены. Дубликаты сравниваются внутри выбранного провайдера по dial IP, порту, UUID, TLS-имени и pin сертификата. Совпадающие настройки с другими названиями считаются одним выходом. Названия импортированных выходов формируются из номера строки, IP и порта. Подтвердите добавление в каталог в течение 10 минут при неизменном черновике. После перезапуска API сделайте предпросмотр заново. Добавление сохраняет существующие выходы и текущий выбор. Для смены трафика отдельно выберите выход, проверьте изменения конфигурации и примените их.

Загрузка разовая, с проверкой TLS по публичному имени на HTTPS/443. Запрос закрепляется за проверенным публичным IPv4 и не следует redirects. Если провайдер требует редирект, сжатие, нестандартный порт или IPv6-only, используйте вставку содержимого. Лимиты: 24 КиБ для вставки, 128 КиБ для скачивания, до 256 строк с записями и до 64 сохранённых выходов во всём каталоге. Ссылка подписки и исходный текст не записываются в БД. Учётные данные добавленных выходов шифруются ключом Working Core.

## Проверки · 2026-11-20

Локально прошли 62 целевых backend-теста, 146 frontend-тестов, lint, сборка и проверка diff. Тесты загрузки подменяют DNS и TLS-поток. Сценарий каталога использует SQLite и подмену Agent. Проверены закрепление проверенного IPv4, TLS-имя, отказ для redirects и непубличных DNS-ответов, таймаут, лимиты размера, сохранение текущего выбора и защита от устаревшего подтверждения.

Для проверки на согласованной disposable VM импортируйте тестовую HTTPS-подписку со смешанными записями. Убедитесь, что исходный трафик идёт через прежний выход после импорта. Затем выберите добавленный выход, отдельно примените конфигурацию и проверьте маршрутизацию и отказ без DIRECT fallback. Блок B остаётся в работе.
